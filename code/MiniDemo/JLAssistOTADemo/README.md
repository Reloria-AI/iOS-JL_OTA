# AI Glasses BLE Demo

这个 Demo 基于仓库里现成的 `JLAssistOTADemo` 改造，用来快速验证 AI 眼镜协议是否能够联通。

## 当前能力

- 扫描 BLE 设备并连接（兼容 `AA12/AA13/AA14` 和实机可能出现的 `AE00/AE01/AE02`）
- 自动订阅命令通知特征
- 识别 `AA15` 图片数据读特征，便于后续联调缩略图/高清图
- 使用 `AA13` 发送自定义协议包
- 自动发送 `0x59` 同步手机时间
- 预置常用命令：
  - 设置 LED 亮度
  - 设置 1 分钟录像时长
  - 开启佩戴检测 / 语音命令
  - 获取电量
  - 获取版本
  - 拍照 / 高清拍照
  - 开始录像 / 停止录像
  - 打开 Wi-Fi AP / P2P
  - 获取缩略图数量
  - 获取设备状态 / 开关状态
  - 获取直播支持 / 当前音量 / 项目名
- 查看 BLE 原始 Hex 日志
- 手动输入原始 Hex 发包
- 基于协议里的本地 HTTP 地址拉取文件列表
- 在 App 内加载并显示最近文件的缩略图/原图

## 协议假设

根据你补充的新指令结构，命令包目前按以下方式组包：

- 下发包头：`AB 55`
- 上行包头：`AC 55`
- 长度：2 字节，大端，内容为 `cmd + payload + checksum`
- 无 data 的命令，当前按备注补 `0x00`
- 校验：`cmd + payload` 按字节累加后 `& 0xFF`

说明：

- 当前发包已取消命令尾部字段，直接按 `包头 + 长度 + 指令 + 数据 + 校验` 发送
- 收包解析仍兼容“无尾部”以及此前 OCR 里疑似存在的 `55 AB / 55 AC` 尾部，便于联调
- 文件通道单独按 PDF 中的 `52 58 ... 58 52` 结构解析

如果设备没有响应，可以直接用页面里的“发原始 Hex”手动调整包格式验证。

## Wi-Fi 相关

- AP 模式主机：`192.168.1.254`
- P2P 模式主机：`192.168.49.207`
- 文件列表接口：`/?custom=1&cmd=3015`

## 实机联调建议

1. 打开 App 后先点“扫描”
2. 连接眼镜
3. 看日志里是否出现 `AA12 / AA13 / AA14`
4. 先试 `同步时间`、`取电量`、`设备状态`
5. 要看图片时，先 `开 AP / 开 P2P`，手机接入眼镜 Wi-Fi，再点 `拉文件列表`
6. 文件列表解析出路径后，点 `加载缩略图` 或 `加载原图`
7. 如果没回包，复制页面显示的 Hex，结合厂家协议手动微调后通过“发原始 Hex”测试
